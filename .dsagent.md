PROJECT BRIEF (read before acting) — /home/mateyfasito/dev/game

Small personal pixel-art games. Owner writes casual Argentine Spanish; in-game text in Spanish, code and identifiers in English.

Stack (always, unless the task says otherwise):
- Three.js + Vite (npm). Plain JavaScript ES modules, no TypeScript, no frameworks, no extra deps beyond `three` and `vite` unless strictly needed.
- 2D pixel art rendered with Three.js: OrthographicCamera, internal resolution 480x270 (Stardew-like view: ~30x17 tiles of 16 px on screen) scaled by an integer factor to fit the window (if the window is smaller than 2x, allow 1x and center), textures with `magFilter = minFilter = THREE.NearestFilter`, `generateMipmaps = false`, `colorSpace = THREE.SRGBColorSpace`, renderer `antialias: false`, sprites on PlaneGeometry with integer pixel positions (round before render).
- Input: Gamepad API FIRST (left stick + d-pad move, deadzone 0.25; button 0 = A = interact/confirm; button 1 = B = back; button 9 = Start = pause), keyboard fallback (WASD/arrows, E/Enter/Space = interact, Esc = pause). One input module `src/input.js` exposing a polled state per frame, so every scene reads the same API.

Art direction: FIRST AND FOREMOST faithful to the El Eternauta comic (Oesterheld / Solano López, 1957): refs eternauta/ref/comic_*.png (look at them). Characters must be recognizable from the comic. AUTHORITATIVE descriptions: section "Personajes" in eternauta/docs/guion.md (made from the scan; e.g. Lucas is a middle-aged, balding bank clerk with light hair, NOT young). Always check the cited comic pages. The suit is THE icon: full-body heavy waterproof suit with a ROUND DOME HELMET / diving-style glass visor framed in metal, a breathing hose/valve at the mouth, thick gloves and boots, often carrying a rifle. Mood: 1950s Buenos Aires suburb (Vicente López), night, deadly glowing snow, empty streets, chalets, fences, cars of the era. SIMPLICITY WITH DETAIL (the key of Stardew-like pixel art): big, clean, flat color areas with a FEW well-placed detail pixels. Concretely:
  - Limited palette per object (3-4 tones of one hue: base, shadow, deep shadow, 1 highlight). Hue-shift shadows (cooler/purpler), highlights warmer. No gradients, no dithering noise, no random speckle.
  - Readable silhouettes first; detail only where the eye goes: faces (2-px eyes, 1-px highlight), hands, the helmet visor glint, wood grain as sparse 1-px lines, a few snow sparkles.
  - Colored outlines one step darker than the fill (not black); selective outline (lighter on lit side).
  - Light from top-left; consistent 1-px rim/shadow on every object; soft round drop shadows under characters and furniture.
  - Repetition with variation: tiles/planks repeat but vary slightly (every 3rd plank a tone off, a knot here and there).
  - If something looks busy, remove pixels; if flat, add ONE highlight and ONE shadow line.
SCALE (very important, the owner said everything was too big): everything lives on a 16 px TILE GRID. A character is 1 tile wide x 2 tiles tall (16x32). A chair ~1x2 tiles, a table for 4 ~3x2 tiles, a radio 1x1-2, a window 2x2, a door 1x2, small items on the floor/shelves 8-16 px. Rooms and streets are MAPS bigger than the screen (e.g. attic ~36x22 tiles, street ~80x20 tiles) with a camera that follows the player smoothly and clamps to map edges. Many small detailed objects with walkable space between them, so it's comfortable to move around and interact (like Stardew's shop/farm screens). UI is small too: hotbar slots 18-20 px, font ~6-7 px tall, dialog box at most ~1/3 of screen height.
The RENDERING technique is Stardew Valley-LIKE (inspiration only: never copy its sprites, characters or UI art). 3/4 top-down, warm saturated palette, colored dark outlines (not pure black), 3-4 tone shading per material, chunky readable silhouettes, characters ~16x32 at 1x with 4-direction walk cycles. Reference screenshots for style only: eternauta/ref/*.png. All art is generated by Python pixel-grid generators (no hand-drawn files), starting from the existing sprites, palettes and layouts in bocetos/:
- bocetos/eternauta/*.png (320x180 mockups: titulo, altillo, calle, sprites; sprites_tira_1x.png is a 32x192 strip) and the generator scripts bocetos/eternauta/scripts/*.py (lib.py has PAL palette + SCALE; chars.py has character grids and walk frames).
- bocetos/cruce/ (another game: generar.py + pixlib.py).
- To get game assets, write a Python exporter under the game's tools/ folder that imports those scripts (sys.path insert, PIL) and writes 1x PNGs (individual frames / sprite sheets / backgrounds) into the game's public/assets/. Do not hand-draw new art if a generator already has it. Mockup PNGs may be used directly as backgrounds.
- NEVER edit or delete anything inside bocetos/.

HAND-EDITED SPRITES (Eternauta, takes precedence over everything below): if eternauta/art/sprites/<sheet>/ exists, those PNGs are the source of truth for that sheet (the owner edits them in LibreSprite). Never regenerate or overwrite them from Python; rebuild the sheet with `npm run sprites:pack` (see eternauta/docs/sprites_pipeline.md). New art goes in as new PNGs there. The in-game sheets (public/assets, e.g. chars2) are the latest art; most of art/concept/out is outdated.
ART SOURCE OF TRUTH (Eternauta): eternauta/art/concept/*.py (concept generators made by the art director) and eternauta/art/direccion/Eternauta-direccion-de-arte.pdf. Reuse those generators (import them) instead of drawing new art; anything missing must follow the same palettes and rules. Projection is oblique 3/4 top-down (no vanishing points, roofs as rectangles/parallelograms going UP the screen, front-facing gables). Full spec for the demo: eternauta/docs/diseno_sw.md and eternauta/docs/guion_demo.md.

Rules:
- Keep it simple ("simplón"), small files, clear names, no over-engineering.
- Never launch an interactive browser/window. Verify with `npm run build` (must pass with no errors) and `node --check` on files, plus small node tests of pure logic when useful.
- `npm run build` passing does NOT mean anything renders. Every visual change must be checked with a HEADLESS screenshot: start `npx vite --port 5199 --strictPort` in the background, then drive it with playwright-core (executablePath ~/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome, args --use-angle=swiftshader --enable-unsafe-swiftshader), press keys, save PNGs and look at them (non-black, sprites visible). Kill the server after.
- Three.js gotcha: the camera here is Y-down (top=0, bottom=view height). That flips triangle winding, so every material needs `side: THREE.DoubleSide` and every texture `flipY = false`, or nothing is drawn.
- Do not use sudo. Do not install global packages.
- Ground historical/story content in the real source material; do not invent facts about it.
